# 产品北极星

`xshow` 是一个从信号、电路、机器到算法的交互式计算机科学可视化平台。

这句话是当前项目的方向锚。它不是营销文案，而是用来判断功能取舍、信息架构和技术路线的主线。

## 初心

项目最初的直觉，是把计算机科学里那些常被抽象掉的层次重新变成可观察、可操作、可推演的东西。

这条路可以从一个很小的信号开始：

1. 一束光、一个开关、一条线
2. 电路里的通断、方向、测量和故障
3. 逻辑门、锁存器、寄存器和存储
4. ALU、FLAGS、PC、内存和指令周期
5. 汇编程序如何一步步改变机器状态
6. 算法和数据结构如何落到内存、寄存器和执行过程上

这里可以受到《编码：隐匿在计算机软硬件背后的语言》和《计算机程序设计艺术》这类经典作品启发，但 `xshow` 应该做原创的交互式演示、练习和可视化，不复刻书中原文、页面结构或题解。

## 主线层次

### 1. 信号与电路层

目标：让用户理解“状态如何通过连接传播”。

已有基础：

- 电路工作台
- 元器件拖拽、连线、通断和测量
- 导线电流动画
- 维修任务和故障诊断

这层是整个项目的地基。`src/lib/circuit.ts` 的角色不是一个孤立电路玩具，而是“从信号出发”的第一层可验证模型。

### 2. 逻辑与存储层

目标：把电路里的信号组合成布尔逻辑和可记忆状态。

已有基础：

- `/logic-lab`
- AND / OR / XOR / NOT 真值表
- SR latch 状态保持预览
- 1-bit register 上升沿采样预览

候选能力：

- flip-flop
- 时钟、边沿、寄存器
- 小型 RAM 或内存单元演示

这层负责连接“电路为什么能表达逻辑”和“机器为什么能保存状态”。

### 3. 机器层

目标：让用户看到一台小计算机如何运行。

已有基础：

- `modules/cpu-sim`
- 8-bit CPU
- A/B/PC/FLAGS
- 256 字节内存
- 汇编器、执行日志、寄存器和内存面板

这层已经进入主站预览，而不是普通探索实验。长期更适合走 Rust/WASM 核心 + Vue/TypeScript 前端，让机器模型稳定、可测试、可嵌入 Web/PWA。

### 4. 算法层

目标：让算法不只是一段代码或一段动画，而是可以下钻到机器行为。

候选能力：

- 栈、队列、链表、树、哈希表
- 排序、搜索、递归、回溯、图算法
- 数组变化、内存读写、寄存器变化和指令执行同步展示

理想体验不是只看“算法动画”，而是可以从算法一路看见程序、机器和信号。

## 技术路线判断

短期主应用仍应保持 Web/PWA 优先，因为这让首次打开、移动端访问和静态部署都更简单。

但“机器层”和未来算法执行器不应轻易丢掉 Rust 的价值。更推荐的长期方向是：

```text
Rust core -> WASM bridge -> Vue/TypeScript UI
```

这样可以同时保留：

- Rust 核心的确定性、性能和测试优势
- Web/PWA 的访问便利
- 未来 Tauri 桌面壳的可能性

## 优先级原则

- 能强化“信号 -> 电路 -> 机器 -> 算法”主线的事情优先。
- 探索实验可以存在，但要清楚标识，不要模糊主入口。
- 新功能要能回答“它让哪一层更清楚？”。
- 先让主线可讲、可用、可验证，再追求更大的覆盖面。
- 每次大方向变化都应该沉淀到文档里，避免后续反复重新发现项目初心。
